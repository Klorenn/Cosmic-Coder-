# Pixel-art assets (v2)

Enemy / mini-boss / boss / XP-gem sprites and hit-flash silhouettes are generated by
`scripts/assets/gen-sprites.mjs` (Node + `sharp`); item icons come from `scripts/assets/gen-items.mjs`
(32x32, see below). Every gen-sprites sprite is drawn on an
indexed grid with a shared 16-colour cyber palette (cyan / magenta / acid green / error red + navy,
purple, slate, amber, orange, white), a 1px dark outline (`#0a0614`) and a 1px transparent margin.
Output is deterministic: re-running the script yields identical PNGs.

Manifests (single source of truth for keys, files, frame sizes and fps):

- `src/scenes/boot/enemyAssets.js` — `ENEMY_SPRITES`, `ITEM_ICONS`, `PROCEDURAL_TEXTURES`,
  `preloadEnemyAssets(scene)`, `createEnemyAnims(scene)`, `preloadItemIcons(scene)`.
- `src/scenes/boot/characterAssets.js` — `CHARACTER_HIT_SHEETS`, `preloadCharacterAssets(scene)`,
  `createCharacterAnims(scene)`, `playHitFlash(scene, sprite, ms)`.
- `src/data/enemies.js` — each enemy / mini-boss / boss has `texture`, `anim`, `frameWidth`, `frameHeight`.

`src/__tests__/assetsManifest.test.js` checks every texture referenced in `enemies.js` / `items.js`
exists as a PNG with the right dimensions (or is a declared procedural texture).

## Regenerate

```bash
node scripts/assets/gen-sprites.mjs                       # enemies, bosses, XP gems, hit sheets (never items)
node scripts/assets/gen-sprites.mjs --only=glitch,xp-gem-blue,player-hit-v2
node scripts/assets/gen-items.mjs                         # 32x32 item icons (pixel kit v3)
npx vitest run src/__tests__/assetsManifest.test.js
```

To add a sprite: add an entry to the manifest, add a `draw(grid, frame)` function in the generator
(`ENEMY_DRAW` / `MINIBOSS_DRAW` / `BOSS_DRAW`), run the script, look at the PNG at 4x. Item icons are
not in gen-sprites any more (the old 16x16 `ITEM_DRAW` / `-v2` icons were removed so a default run cannot
overwrite the 32x32 art); `--only=item-*` is ignored with a warning.
The script fails if a sprite uses more than 16 colours or a hit sheet frame count mismatches.

## Weapons v2 — pixel art (`public/assets/sprites/weapons/`)

Weapons, projectiles, melee, evolutions, legendaries and icons are hard-pixel art (Vampire Survivors /
Celeste style): limited ramp per weapon (outline, dark, mid, light, highlight, white), automatic 1px dark
outline, 1-2 rings of light pixel glow (translucent but hard-edged), 2-4 frame animations that change the
silhouette (tail length, flare, spin, flicker). No gradients, no supersampling. Art is drawn on small grids
and nearest-upscaled so in-world sizes and hitboxes stay the same as before: x2 for projectiles (24x24 art),
swings, orbs, auras (128 art), beams, drops (20x20 art) and `slash`; x3 for icons (32x32 art with a 1px
bevelled frame, gold frame for evolutions); x1 for legendaries (like the hand-made 32px Warglaive).
Filtering stays NEAREST (global `pixelArt: true`; weaponAssets.js sets no filter). Colours come from
`src/data/weapons.js` (`color`); very light colours get a steel mid-tone for contrast.

```sh
node scripts/assets/gen-weapons.mjs           # 34 strips + 69 images (deterministic)
node scripts/assets/gen-weapons.mjs --sheet   # + scripts/evil-player/reports/weapons-sheet.png (2x)
node scripts/evil-player/screenshot-weapons.mjs  # staged in-game shots hud-weapons-<id>-1280x720.png
```

Manifest: `src/scenes/boot/weaponAssets.js` (`preloadWeaponAssets` in BootScene.preload,
`createWeaponAnims` in BootScene.create: anims only).
BootScene's procedural `generate*WeaponTexture` functions now return early when the PNG loaded
(they are the fallback). `legendary-huntersWarglaive` is the hand-made `public/assets/hunters-warglaive.png`
(was never loaded before).

### ArenaScene wiring (pending — ArenaScene is owned by other agents)

Without wiring, every shot is the new white `slash` tinted with the (new palette) weapon colour.
To get one silhouette per weapon, in `autoAttack()` (both `this.projectiles.create(..., 'slash')`
calls) and in the fork-bomb child spawn:

```js
// helper (ArenaScene method)
applyWeaponArt(projectile, weapon) {
  const key = weapon.texture;
  if (!key || !this.textures.exists(key) || key.startsWith('aura-') || key.startsWith('orb-')) {
    projectile.setTint(weapon.color);       // legacy look
    return;
  }
  projectile.setTexture(key, 0);
  projectile.clearTint();
  const anim = `${key}-anim`;
  if (this.anims.exists(anim)) projectile.play(anim);
  if (projectile.body) projectile.body.setSize(40, 40, true); // keep the old `slash` hitbox
}
// replace `projectile.setTint(weapon.color);` by `this.applyWeaponArt(projectile, weapon);`
// (melee branch keeps body.setSize(48, 48) after the call)
```

Orbitals (`createOrbitals`): replace `this.add.circle(0, 0, 12, weapon.color)` by
```js
const orbital = this.textures.exists(weapon.texture) && weapon.texture.startsWith('orb-')
  ? this.add.sprite(0, 0, weapon.texture).play(`${weapon.texture}-anim`)
  : this.add.circle(0, 0, 12, weapon.color);
```
and, for `weapon.aura` (ringoffire / deathaura), one extra sprite following the player in
`updateOrbitals` (`setDisplaySize(176)` for ringoffire = orbit radius 80; `radius * 2` for deathaura;
destroy it in `clearOrbitals`). AoE (`doAoeAttack`): swap the `add.circle` ring for
`this.add.sprite(x, y, weapon.texture).play(...).setDisplaySize(radius * 2, radius * 2)` (integer multiples of 256/2 keep pixels even)
when `weapon.texture` starts with `aura-` (fade alpha 1 -> 0 over 300 ms; no scale tween needed).
Menus: TitleScene `buildIcon` can prefer `weapon-icon-${it.key}` (96px pixel icon, cleaner than the 40px drop). Pixel art reads best without ADD blend (outlines would vanish).

## Pixel UI kit v3 (`public/assets/UI/pixel/`)

### Using the kit (HUD / game over / any scene)

Sizes are logical units; `px` = logical units per art pixel. Pick one art scale per screen and keep it
(overlays use 2 css px per art px: `px = 2 * overlayUnit(scene)` from `title/overlayKit.js`; in a
1920x1080 FIT canvas, `px = 3` is 2 css px at a 1280 px window, `px = 2` at 1920).

```js
import { pixelText, pixelPanel, uiIcon, uiSprite, ditherFill, pixelDivider, familyOf, buttonSkin,
  selectedCardSkin, progressFillSkin, tileSkin, PX, PX_CSS } from './boot/uiAssets.js';

const panel = pixelPanel(scene, x, y, 320, 120, 'panel-dark', { px: 3 }); // Container, top-left origin
panel.resize(360, 120); panel.setSkin('panel-accent');
const title = pixelText(scene, x + 18, y + 16, 'GAME OVER', { size: 8 * 4, color: PX.red }); // size = 8 * art scale
const hp = uiIcon(scene, x + 30, y + 60, 'heart', { px: 2 });            // full colour, centred
const lockedIcon = uiIcon(scene, 0, 0, 'sword', { px: 2, tint: PX.slate }); // greyscale ramp tinted
const bar = pixelPanel(scene, x, y, 200, 6 * 3, 'progress-track', { px: 3 });
const fill = pixelPanel(scene, x, y, 200 * pct, 6 * 3, progressFillSkin('green'), { px: 3 });
const btnBg = pixelPanel(scene, bx, by, 160, 20 * 3, buttonSkin('violet', 'normal'), { px: 3 }); // hover/pressed: setSkin()
const dim = ditherFill(scene, 0, 0, w, h, { px: 3, color: PX.ink, alpha: 0.55 });
```

`pixelText` returns a BitmapText with Text-like shims (`setColor`, `setFill`, `setShadow` -> hard 1 art px
ink shadow, `setWordWrapWidth`, no-op `setFontStyle/setStroke/setPadding`), so it can replace
`scene.add.text` in UI code. Unsupported characters are folded (`Á`->`A`, smart quotes) or dropped (emoji).
Higher-level widgets with the old glass API (`createOverlay`, `glassCard`, `pillButton`, `toggle`, `slider`,
`segmented`, `keycap`, `dotsLevel`, `miniBar`, `medalIcon`, `skeletonBar`, `pixelIcon`, `gemIcon`, `ovText`,
plus `iconTile`, `pixelDisc`, `mixColor`, `artPx`) live in `src/scenes/title/overlayKit.js`.

### Arena pixel HUD / banners / game over (ui/arena-pixel-v3)

ArenaScene draws every in-run sign with the kit at **2 css px per art px**: `computeHudLayout()` and
`computeGameOverLayout()` expose `px` (logical units per art pixel) and every position is snapped to it.
Pure helpers in `src/systems/hud/pixelShapes.js`: `artPxFor`, `snapPx`, `stepsFilled` (12-step rings),
`ringCells` / `ringRuns` / `drawSegRing` (segmented pixel rings, merged into row runs), `discRows` /
`drawPixelDisc` (bevelled discs), `fadeSteps` (alpha 1 / .75 / .5 / .25 / 0).

- HUD: `panel-dark` vitals with the portrait in a `well` (head framed from frame 0's opaque bbox),
  `progress-track` + `progress-fill-green|amber|red` HP, `progress-fill-violet` XP + level `chip`,
  "WAVE n" and score (`ui-star`) in `chip`s, weapon / ability as pixel discs with 12-step rings, buffs as
  `item-<id>` (32 px, NEAREST, 1 css px per texel) inside segmented duration rings, boss bar `progress-fill-red`
  with name + phase pips. The pixel layer is only redrawn when its quantised state changes.
- Banners (`showHudBanner`): `panel-accent`, 2x pixel title, accent diamonds; 2-frame entry and stepped fade.
- Floating texts (`floatText`, `showItemText`, crits): world-space pixel font, 4-step rise + stepped fade.
- Game over: dithered ink veil, `panel-dark`, amber 3x title with a 2-step hard shadow, `tile-<family>` stats
  with kit icons, rank `chip`, NEW BEST on `button-amber-normal`, kit buttons with the `cursor` sprite as focus,
  status line with a tinted kit icon (`shield` amber when unverified). The bot finds the `GAME OVER`
  BitmapText (`scripts/evil-player/run.mjs` accepts Text or BitmapText).
- Pause: dithered veil, `panel-dark`, 3x "PAUSED", kit buttons + blinking `cursor`; settings use `card` rows
  and `toggle-on|off` sprites. Item textures stay NEAREST (`ensureSmoothTextures` no longer smooths `item-*`).
