# Maps and biomes

One biome per stage (`src/data/stages.js` → `src/data/biomes.js`, same index). Each biome has its own
background, border/wall tile, 2 obstacles, 2 hazards and 1 mechanic.

| # | Biome (`id`) | Background (far / near) | Obstacles | Hazards | Mechanic |
|---|---|---|---|---|---|
| 0 | DEBUG ZONE (`debug-zone`) | cold blue-cyan nebula, star field / faint cyan aurora ribbon, bokeh dust | codeBlock, terminal | bugSwarm, nullDeref | `boostZone`: speed x1.25 inside zones |
| 1 | MEMORY BANKS (`memory-banks`) | deep violet nebula with magenta highlights / crystalline dust clumps | serverRack, memoryStick | memoryLeak, heapFragment | `slowZone`: speed x0.55 inside zones |
| 2 | NETWORK LAYER (`network-layer`) | electric-blue nebula + very faint light threads / brighter light threads with sparks | routerBox, cableBundle | packetStorm, packetLoss | `teleport`: paired zones, 2.5 s cooldown |
| 3 | KERNEL SPACE (`kernel-space`) | dark red-amber nebula with embers / rising embers + heat wisp (near layer pulses at runtime) | cpuCore, registerBlock | kernelPanic, thermal | `pulseDamage`: 12 dps for 1 s every 3 s inside zones |
| 4 | CLOUD CLUSTER (`cloud-cluster`) | blue-lavender nebula + ethereal cloud veils / translucent cloud veil | cloudServer, apiPortal | latencySpike, coldStart | `wind`: global rotating push |
| 5 | SINGULARITY (`singularity`) | black-violet, soft vortex + faint accretion disk at the centre / curving dust lanes, gold specks | voidFragment, eventHorizon | blackHole, entropyField | `gravity`: global pull to world centre |

The mechanic logic is the pure `biomeEffect()` in `src/systems/MapManager.js`.

**Arena background (since the space-background rework)**: the arena no longer draws the far/near biome
tiles above. It uses the title-screen look — the animated pixel space background of
`src/systems/spaceBackground.js` — with one palette variant per stage (`biome.bgVariant`):

| Variant | Palette | Props |
|---|---|---|
| `debug-zone` | navy / blue-cyan + violet (the title-screen nebula) | planet, asteroid, ringed planet |
| `memory-banks` | violet / magenta | planet, asteroid, ringed planet |
| `network-layer` | electric blue / cyan | planet, asteroid, ringed planet |
| `kernel-space` | dark red / amber | planet, asteroid, ringed planet |
| `cloud-cluster` | sky blue / lavender | planet, asteroid, ringed planet |
| `singularity` | black / violet, gold stars | vortex (black hole), asteroid, ringed planet |

The column "Background (far / near)" above describes the legacy tiles, which stay generated and loaded
for compatibility (ArenaScene checks `biome-<id>-far` to skip its old `arena-bg-*` image).

draws that object with the old `graphics` shapes instead, so the game still runs.

## Art style (v3, "polished deep space")

The characters and enemies are pixel sprites; the environment is deliberately smooth so they stand out.
No grids, scanlines, glitch tears or hard pixels in map art.

- **Palette**: base deep blue-black `#070a1a`; accents violet `#8b5cf6`, cyan `#22d3ee`, magenta `#e879f9`;
  amber `#f59e0b` (and red) is reserved for danger (hazards, `pulseDamage`). Biomes differ only by hue and
  nebula/star density.
- **Far layer** (opaque): 2–3 domain-warped fractal-noise nebula layers modulated by a low-frequency
  density field, smooth dark dust lanes, and a star field of gaussian-haloed points in three sizes (the
  biggest with a soft diffraction cross). Per-biome detail: faint light threads (network), embers (kernel),
  cloud veils (cloud), a centred vortex with a faint accretion disk (singularity).
- **Near layer** (alpha, ≤ ~35 % opacity): faint nebula, fine dust, out-of-focus bokeh discs and one
  identity element (aurora ribbon, crystal dust, light threads, embers, cloud veil, dust lanes). It is
  world-locked and repeats every 512 px, so nothing in it is a single large recognisable object.
- **Obstacles**: lit volumes with a light from the upper left, rim light in the biome accent, outer glow and
  a soft drop shadow: faceted crystals (codeBlock, serverRack, memoryStick), orbs/planetoids with rings
  (terminal, routerBox, cloudServer, eventHorizon), asteroids with glowing cracks (cpuCore, registerBlock,
  voidFragment), light tori (cableBundle, apiPortal). Crate: a rounded supply pod with a cyan seam and an
  amber lamp.
- **Hazards**: soft glowing areas whose edge marks the radius, animated with periodic terms so the
  4 frames loop (expanding rings, plasma puddles, orbiting motes, arcs, dashes, vortex, twinkles).
- **Mechanic zones** are gameplay signs, so they are the exception: crisp pixel art (see "Mechanic zones").
- **Borders / walls**: calm, low-contrast energy slab with faint filaments, opaque, tileable 32x32.
- Everything is antialiased (4x4 supersampling for sprites, gaussian splats for backgrounds). Hazard and
  zone textures are drawn 3–4x larger than their source size; with `pixelArt: true` they are
  nearest-sampled, so giving the `map-*` and `biome-*` textures LINEAR filtering would make them
  look smoother still.

## Runtime

- **Space background** (`createSpaceBackground(scene, { variant, depth, quality })`, owned by MapManager as
  `mapManager.space`; `bgFar` / `bgNear` alias its back / near layers). Three camera-fixed `tileSprite`s
  sized to the view (`/ zoom` + 64 px), from `SPACE_BG` in `biomes.js`:
  back (parallax 0.15, tileScale 3, drift 2 px/s, tinted to 82 % so gameplay reads on top),
  stars (0.4, tileScale 2, twinkle = swaps `stars-a`/`stars-b` every 520 ms),
  near wisps (0.7, tileScale 3, alpha 0.45). Tile offset = `(camera.scroll * parallax + drift * t) / tileScale`.
  Plus ≤ 6 drifting props (own parallax 0.21–0.35, depth between stars and near) and ≤ 40 motes
  (pooled 3x3 images, 3-step pulse). No per-frame `Graphics`. Depths -9.5 … -9.45. Driven by
  `space.update(delta)` on the scene `postupdate` event (`MapManager.syncParallax`).
- **Waves**: `mapManager.onWaveChanged(wave)` → `space.setWave(wave)`: nebula brightness cycles ±10 % over
  5 waves (back tint, near alpha), motes 16 → 40 with it, and every 5th wave a new prop floats in from
  the right (oldest dropped past 6). Pure rule: `waveMood(wave)`.
- **Quality**: `mapManager.setQuality('low')` (qualityGovernor) → no motes, no twinkle, near layer hidden.
- **Title screen** uses the same module in `mode: 'title'` (`TitleScene.createBackground`): the original
  cover-image composition with the `bg-blue-*` art, unchanged look.
- **Borders**: four 32 px `tileSprite` strips along the world edge (visual only; the world bounds
  already stop the player). Walls use the same tile.
- **Stage change**: `mapManager.transitionToStage(stage)` crossfades the space background to the new
  variant (600 ms in 4 hard alpha steps, retro), fades the old borders out, rebuilds the map around the
  player's current position, fades the new objects in and rewires collisions.
- `setupCollisions()` can be called more than once: each call replaces the previous colliders.

## Mechanic zones (readability)

Players must understand a zone at a glance, without text. Each zone is small (radius 70-90 px, 1-2 per
map, never within `spawnClearance` of the spawn) and is drawn as a translucent pixel disc with a dotted
border that slowly rotates, in the colour of its effect, plus a 16x16 pixel icon at 4x in the centre.
Data: `ZONE_STYLE` (colour, player tint, label key) and `LAYOUT_RULES.zones` in `biomes.js`.

| Mechanic | Disc / icon | While inside | First time this run |
| --- | --- | --- | --- |
| `boostZone` | cyan, double chevron ▲▲ (bright chevron alternates) | speed x1.25, player tinted light cyan | `zones.boost` "SPEED UP" |
| `slowZone` | violet, hourglass with running sand | speed x0.55, player tinted lavender | `zones.slow` "SLOW" |
| `pulseDamage` | amber skull while idle; disc + skull turn red (hot eyes) while the pulse hurts | 12 dps during the 1 s pulse, player tinted red | `zones.damage` "DAMAGE" |
| `teleport` | portal pair: both ends share one colour, pixel letters A / B mark the ends | teleports to the other end | `zones.teleport` "TELEPORT" |
| `wind` (global) | no disc; three lavender wind streaks beside the player, rotated to the push | pushed | `zones.wind` "WIND" |
| `gravity` (global) | violet disc + spiral marks the pull centre (world centre); small spiral beside the player points at it | pulled | `zones.gravity` "GRAVITY" |

- Teleporter pads use the same pair language: pair 0 cyan, pair 1 magenta (`PORTAL_PAIR_SIDES`). The
  teleport biome gets one pad pair (`LAYOUT_RULES.teleporterPairsTeleportBiome`); its zones are the second.
- The label is the scene's `floatText` (pixel text, 1.2 s) and shows once per zone type per run
  (`mapManager.seenZoneTypes`); every entry also emits `scene.events.emit('zone:enter', { type })`.
- The tint only touches a tint MapManager set itself (sudo / shrine tints are left alone) and is cleared
  on exit and on map change. All of this runs in `MapManager.updateZoneFeedback`, called from
  `getBiomeEffect` (a few property writes per frame, no Graphics).
- Captures: `node scripts/evil-player/screenshot.mjs` writes `hud-zone-<stage>-<viewport>.png` (`HUD_ZONES=0` to skip).
- Art: `node scripts/assets/gen-biomes.mjs --zones` regenerates only the zone discs + icons.

## Map layout

`layoutBiome(seed, biome, w, h, { stage, spawn, teleporterPairs })` in `MapManager.js` is pure and
seeded (mulberry32). It returns `{ walls, obstacles, hazards, zones, crates, teleporters }`.
Its rules come from `LAYOUT_RULES` in `biomes.js`:

- every item edge is at least `spawnClearance` (200 px) from the spawn point
- items never overlap (bounding circles plus a 24 px gap) and stay inside `edgeMargin`
- count = `round(base * biome.density * (1 + stage * 0.15))`, so later stages are denser
- teleporter pads come in pairs placed in different quadrants, and teleport-mechanic zones always
  come in complete pairs

`generateMap(stage, { seed })` reproduces a layout exactly. The seed used is kept in
`mapManager.layoutSeed`. Tests: `src/__tests__/BiomeLayout.test.js`.

## Regenerating art

```bash
node scripts/assets/gen-space-bg.mjs           # arena/title space background variants + props + mote
node scripts/assets/gen-space-bg.mjs --sheet   # also scripts/evil-player/reports/space-bg-sheet.png
```

Space background: deterministic Node + sharp, hard pixels only (4x4 Bayer ordered dithering over a 6-tone
ramp + 3-tone accent per variant, palettes in `SPACE_PALETTES`), periodic value noise so tiles are seamless.
Tests: `src/__tests__/spaceBackground.test.js` (helpers, fade/twinkle/drift/wave/quality, files on disk).

Legacy biome tiles + map sprites:

```bash
node scripts/assets/gen-biomes.mjs                       # rewrite every PNG
PREVIEW_DIR=/tmp/prev node scripts/assets/gen-biomes.mjs --preview   # also 2x2 tiled previews to check seams
node scripts/assets/gen-biomes.mjs --sheet               # also scripts/evil-player/reports/art-sheet.png
```

The script is deterministic: the same code always gives the same pixels. Backgrounds and border
tiles use periodic value noise (lattice indices taken mod the period) and wrapped splats/curves, so
they tile seamlessly by construction. Animated strips loop because every time term is periodic. To add a biome, obstacle, hazard or mechanic,
add its data to `biomes.js` and a recipe to the matching table in the script (`BG`, `OBSTACLES`,
`HAZARDS`, `ZONES`). The script throws on missing recipes, and the manifest test fails on missing files.
